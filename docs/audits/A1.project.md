# A1 overlay — MoMo Kasi

Appended to the shared A1 brief. Project-specific obligations a generic codebase audit cannot know.

## Non-negotiables to check every time

These are `CLAUDE.md`'s standing orders. A violation is at least **High**, regardless of whether it
currently causes a bug — they are structural guarantees, and the whole design rests on them.

1. **No floating-point money.** Any `number`, `numeric`, `float8`, `parseFloat`, `Number(`,
   `toFixed(` applied to an amount, anywhere. Money is `bigint` minor units (ADR-0004).
2. **No stored balances.** A `balance` column, or any table that caches a sum the ledger should
   derive, breaks ADR-0003. Balances come from `SUM(ledger_entry.amount)`.
3. **One ledger writer.** Ledger postings are written in exactly one place, inside the guarded
   `PENDING -> SUCCESSFUL` transition. A second write path is **Critical**.
4. **Guarded state transitions.** Every status change must be
   `UPDATE ... WHERE id = $1 AND status = <expected>`. A read-then-write is a race and is **High**.
5. **Idempotency by construction.** Every outbound MoMo call reuses the persisted
   `momo_transaction.id` as `X-Reference-Id`. A freshly generated id on a retry is **Critical** —
   it double-pays.
6. **The agent cannot move money** (ADR-0014). Any path from a `propose_*` tool to a database write
   is **Critical**.
7. **No unsourced money in an artifact** (ADR-0013). Every rendered amount carries a `sourceTxnId`
   or `sourceAccountId`.
8. **Migrations are forward-only.** An edit to a migration already on `main` is **High**.

## Module boundaries (docs/01 §5)

`src/domain/**` must stay pure. Flag any import of `fs`, `process`, `next`, `react`, a Supabase
client, or anything outside `src/domain`. This purity is what makes the property tests cheap; losing
it quietly is how the test strategy erodes.

Also flag: `app/(app)/**` or any `'use client'` file importing the service-role Supabase client
(ADR-0010). In a **public** repository that is the single most damaging possible mistake.

## What to grade generously

This is a 28-day hackathon build by one developer, deliberately scoped in `docs/00` §7:

- Missing tests on UI components — covered by E2E per `docs/04` §12, by design.
- `TODO(S7c)` style markers that name a `STATUS.md` workstream — that is the tracking system
  working, not debt hiding.
- The mock agent (`src/lib/agent/mock.ts`) — an intentional stand-in, documented as such.
- Absence of KYC/FICA, licensing, HSM key management — explicit non-goals.

Do not report these as findings. Report anything that contradicts a documented decision instead.

## Where the decisions live

Before flagging a design choice as wrong, check `docs/adr/` — there are 15 ADRs, each recording the
options rejected. A finding that re-litigates a decided trade-off without new information is noise.
If an ADR is genuinely wrong, say so and name it.
