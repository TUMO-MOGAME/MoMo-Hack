# A5 overlay — MoMo Kasi

Appended to the shared A5 brief. This is a payments application in a **public** repository, so two
threat classes matter more here than the shared audit assumes.

## 1. Money integrity is a security property

Grade these as security findings, not correctness ones:

| Check | Severity if violated |
|---|---|
| A second code path writes to `ledger_entry` outside the guarded transition | **Critical** |
| A retry generates a new `X-Reference-Id` instead of reusing the persisted one | **Critical** — double payment |
| A state transition is read-then-write rather than `WHERE status = <expected>` | **High** — concurrent resolvers both post |
| `momo_transaction.journal_id` can be set twice | **Critical** |
| A split can produce parts that do not sum to the input | **Critical** |
| An account that forbids negative balances can go negative | **High** |
| The `SUSPENSE` or `ROUNDING` account has a non-zero balance at rest | **Medium** — an alarm, investigate |

## 2. The agent is an untrusted input surface (ADR-0014)

An LLM sits next to a payments flow. Verify **structurally**, not by reading the prompt:

- `propose_*` tools must have **no database write capability at all**. Prompt instructions are not
  a control.
- Proposals must be server-signed (HMAC over amount, payee, purpose, user, expiry) and re-validated
  server-side on confirm. A client-supplied amount that reaches a payment is **Critical**.
- The confirmation card must render from the signed proposal, never from the model's prose.
- No auto-confirm path. No voice-confirm path.
- Prompt-injection surfaces: job titles, stokvel names, Telegram messages and USSD input all reach
  the model. Confirm none of them can reach the DOM as markup (ADR-0013) or alter a proposal.

## 3. Webhooks

- `/api/momo/callback/[kind]` is **untrusted by design** (`docs/03` §3.1). Confirm the body is used
  only to extract a reference id, and that authoritative status is re-fetched from MTN. A callback
  body that directly sets a status is **High**.
- `/api/telegram/webhook` **must** verify `X-Telegram-Bot-Api-Secret-Token`. Missing = **High**.
- `/api/cron/*` must require the `CRON_SECRET` bearer. An unauthenticated cron route is **High** —
  it lets anyone trigger settlement.
- All of the above must be replay-safe: five deliveries of the same payload cause one effect.

## 4. Public repository

The repo is public (ADR-0005). Assume anything committed is scraped within minutes.

- Any secret in git history is **Critical** and requires rotation, not just removal.
- `NEXT_PUBLIC_` on anything sensitive is **Critical**.
- The schema and every RLS policy are readable by attackers. Grade RLS on the assumption the
  attacker has read `supabase/migrations/` — because they can.

## 5. POPIA (docs/14)

South African data protection is in scope for this project. Check:

- MSISDNs never appear in full in logs, URLs, query strings or error messages (s105/106).
- No MSISDN or name appears in an outbound LLM prompt — there is meant to be a scrubber with a test.
- Retention purging actually runs (proof photos 90 days, request bodies 7 days).
- Consent records are append-only and per-purpose.
- Deletion pseudonymises rather than breaking ledger integrity.

## 6. Known and accepted

Do not report these as new — they are documented decisions. Report only if the mitigation is
missing or has regressed:

- MoMo sandbox callbacks are unsigned — mitigated by re-fetching status (`docs/03` §3.1).
- A9 per-PR security review is disabled for cost (`audits.config.json`) — a stated gap.
- No CSP is configured **yet**; flag it if Phase 3 closes without one.
- Sandbox transmits EUR (ADR-0008) — a currency relabel, not an FX bug.
